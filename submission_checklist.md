# Lab 07 - Submission Checklist

## Repository and versions

- [ ] One private repository contains the current project.
- [ ] All three members can clone and run it.
- [ ] Tags exist: `v0-prototype`, `v1-playable`, `v2-tested`, `v3-release-candidate`.
- [ ] `git status --short` is empty at the submitted commit.
- [ ] The final commit hash and repository URL are recorded.

## Core game

- [ ] The game starts with the documented command.
- [ ] One meaningful player action changes state.
- [ ] One success or failure condition is observable.
- [ ] Restart works.
- [ ] The minimum playable loop does not depend on optional polish.

## Engineering evidence

- [ ] At least four contracts are complete.
- [ ] At least six focused tests are meaningful and green.
- [ ] No required test is skipped.
- [ ] One genuine red-to-green debug record is complete.
- [ ] One human playtest and one resulting V3 change are documented.
- [ ] A clean-clone run receipt and known limitation are recorded.

## Collaboration and AI

- [ ] Every member authored at least one reviewed Pull Request.
- [ ] Every member reviewed at least one other member's Pull Request.
- [ ] The role/working contract is complete and signed.
- [ ] Material L1 AI use is recorded with adoption/rejection decisions.
- [ ] No secrets, credentials, fabricated output, or private student data are committed.

## Report and explain-back

- [ ] The report outline includes V0-V3 evidence.
- [ ] A two-minute demo route is rehearsed.
- [ ] Every member can explain one state decision, test, and repair/review decision.
- [ ] Every member can state one limitation and one next-step hypothesis.
